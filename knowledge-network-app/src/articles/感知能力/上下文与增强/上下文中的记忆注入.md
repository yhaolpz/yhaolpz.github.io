# 上下文中的记忆注入

## 一句话定义

把来自记忆系统（短期摘要、用户画像、检索结果等）的文本**按策略插入**当前提示，使模型「带着正确背景」推理。

## 先理解什么（入门）

记忆不等于存数据库：对 LLM 而言，**被写进提示的记忆才算被用到**。注入要回答：何时取、取多少、放在哪、与本轮问题是否相关。

## 再理解什么（进阶）

- **冷启动**：新用户只有设备指纹时，避免注入泛化画像造成偏见。
- **时效**：偏好、项目状态可能过期，需要版本号或时间戳。
- **冲突**：用户口头说「其实我更喜欢 A」与旧画像冲突，要有覆盖策略。

## 落地要点（实践）

- 注入块用明确分隔符，如 `## User memory (verified 2026-04-01)`。
- 与 RAG 区分命名：记忆偏「关于谁」，RAG 偏「关于事/文档」。
- 记录注入快照 id，便于问题回溯。

## 常见坑

- 注入未经审核的第三方爬取数据，带来合规风险。
- 记忆过长淹没当前用户指令。
