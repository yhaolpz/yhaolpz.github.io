# 动态上下文与RAG

## 一句话定义

在对话或任务推进过程中，**按需检索**外部片段并与工具输出一起拼进提示，而不是一次性塞满所有材料。

## 先理解什么（入门）

「动态」相对静态 prompt：用户每问一次、每执行一步工具，上下文都可能变。RAG 提供「从知识库取相关段」；工具输出提供「从系统取事实」。两者都要**裁剪与引用**，否则窗口很快被撑爆。

## 再理解什么（进阶）

- **检索触发**：由模型决定何时查库，或由规则（关键词、意图分类）触发。
- **拼接顺序**：常见做法「系统约束 → 检索片段（带出处）→ 用户问题 → 最近对话」。
- **冲突处理**：检索结果与工具结果矛盾时，要有优先级或二次验证策略。

## 落地要点（实践）

- 每段检索内容附带 `source_id`，便于回答里引用与审计。
- 对长工具 JSON 做摘要再进上下文，保留关键字段原文。
- 监控「检索为空」比例，及时调索引或 query 改写。

## 常见坑

- 检索片段过长导致核心指令被挤出上下文窗口。
- 不标注出处，用户无法核验，信任度下降。
