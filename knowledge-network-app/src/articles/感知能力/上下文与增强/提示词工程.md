# 提示词工程

## 一句话定义

通过**措辞、结构、示例与约束**提高模型在特定任务上的稳定性与可控性，而不是依赖单次运气。

## 先理解什么（入门）

提示词工程不等于「堆长文」。核心是：**任务描述清晰、边界清楚、例子有代表性、输出可解析**。对 Agent 来说，还要考虑与工具 schema、检索片段的协同。

## 再理解什么（进阶）

- **Few-shot**：示例贵精不贵多，2～3 个覆盖主要分支即可。
- **Chain-of-thought 开关**：需要可解释性时打开；要严格控制格式时可要求「先内部思考不输出」或改用 JSON mode。
- **对抗与越狱**：提示里写「忽略上条」类防御并不可靠，应结合护栏与权限。

## 落地要点（实践）

- 用模板变量拆分：角色 / 任务 / 输入 / 输出格式 / 校验规则。
- 对关键路径准备「负例」测试集：模型不应产生的输出。
- 与评测联动：提示变更要对比同一批 golden questions 的通过率。

## 常见坑

- 示例与线上真实分布不一致，导致过拟合演示。
- 中英文指令混用导致优先级歧义。
