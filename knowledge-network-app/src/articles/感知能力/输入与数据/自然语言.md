# 自然语言

## 一句话定义

用自然语言把目标、约束与上下文表达成可执行指令与可检索信息。

## 先理解什么（入门）

Agent 的输入最常见形态就是用户说的话或写的字。模型本身不「看见」你的业务系统，它只看见**被编码进提示里的文本**。因此：自然语言输入的质量，直接决定后续感知、记忆检索与工具调用的上限。

## 再理解什么（进阶）

- **结构化抽取**：从自由文本中稳定抽出「目标 / 约束 / 已知事实 / 期望输出格式」，比单纯「总结一段话」更难，也更有用。
- **指令层级**：系统提示、开发者消息、用户消息、工具回包在上下文中的优先级不同，混用时要避免互相打架。
- **澄清策略**：关键信息缺失时，应先问再执行，而不是猜——尤其在涉及写库、转账、删数据等有副作用操作前。

## 落地要点（实践）

- 把自由文本采集成结构化字段（目标 / 约束 / 输入数据 / 期望输出）。
- 缺信息时先澄清再执行，避免猜测。
- 明确指令层级：系统 > 开发 > 用户 > 工具输出。

## 最小示例

```text
用户：帮我总结这份会议纪要，并列出可执行的行动项

期望输出：
- 3 条要点总结
- 5 条行动项（含负责人/截止时间；缺失则标记「未知」）
```

## 常见坑

- 只做总结不对齐可执行目标。
- 未做确认就调用有副作用的工具。
