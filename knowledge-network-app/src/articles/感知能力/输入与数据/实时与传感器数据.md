# 实时与传感器数据

## 一句话定义

把事件流、指标、传感器读数等**随时间变化**的信号变成模型可理解的「当前状态 + 近期变化」描述。

## 先理解什么（入门）

与「用户一次性提问」不同，流数据是连续的：股价、IoT 温度、线上告警、埋点事件。Agent 无法「全知」整个历史，只能基于**窗口**内的摘要做判断。

## 再理解什么（进阶）

- **时间语义**：必须明确时区、采样间隔、延迟（数据是实时的还是近实时的）。
- **窗口与聚合**：按滑动窗口做 count/sum/percentile，再交给 LLM 解释趋势，比丢原始点列更稳。
- **异常检测**：可先规则或轻量模型打标「异常片段」，再让 LLM 生成运维建议。

## 落地要点（实践）

- 输入侧固定模板：`[时间范围][数据源][聚合粒度][关键 KPI]`。
- 控制突发：对洪峰事件做采样或合并，避免提示抖动。
- 与工具链结合：流处理引擎（Kafka/Flink 等）负责算，LLM 负责解释与决策。

## 常见坑

- 把未对齐时间序列的多路流硬拼成一段文字，模型会错配因果。
- 缺少「正常基线」，模型会把噪声当信号。
