# 多模态输入

## 一句话定义

同时或分别处理图像、语音、视频等多种模态，并在 Agent 链路中**对齐到统一语义**（常为文本或向量）供规划与记忆使用。

## 先理解什么（入门）

「多模态」不等于「把文件丢给一个大模型」。工程上通常是：**专用编码器**（视觉、音频）→ **融合层**（对齐时间轴或空间关系）→ **语言模型** 推理。

## 再理解什么（进阶）

- **模态缺失**：用户只上传图没说话，需要默认任务假设或主动追问。
- **对齐**：视频里「第 12 秒说的话」与画面内容要对齐，可用时间戳索引。
- **成本**：视频逐帧送 VLM 很贵，常见做法是抽帧 + ASR 文本 + 关键帧 OCR。

## 落地要点（实践）

- 为每种模态定义统一元数据：来源、分辨率、时长、语言。
- 优先在感知层做裁剪、压缩、去重，再进核心模型。
- 输出侧明确「模型看见了什么」（例如缩略图描述），便于审计。

## 常见坑

- 高分辨率原图直接入模，latency 与费用不可控。
- 忽略隐私：截图里常含通知栏、聊天列表等敏感信息。
