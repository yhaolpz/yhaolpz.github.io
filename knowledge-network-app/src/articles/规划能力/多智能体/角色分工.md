# 角色分工

## 一句话定义

在多 Agent 系统中为参与者分配**职责边界与决策权限**，如 PM、开发、审查者、SRE 等，以降低混乱与重复劳动。

## 先理解什么（入门）

角色是提示词层面的「人设 + 工具权限 + 输出契约」。分工清晰可减少单模型上下文负担。

## 再理解什么（进阶）

- **RACI 矩阵**：谁负责、谁批准、咨询谁、告知谁，可映射到 agent 流程。
- **动态角色**：根据项目阶段增减 reviewer。
- **冲突解决**：两个 agent 意见相反时由 orchestrator 或人类裁决。

## 落地要点（实践）

- 每个角色绑定允许的工具白名单。
- 输出物命名规范（`design.md`, `api.json`）便于下游消费。
- 记录角色间 handoff 日志。

## 常见坑

- 角色过多每轮都要同步全局上下文，通信量爆炸。
- 权限过大角色被 prompt 注入滥用工具。
