# 任务委派

## 一句话定义

由调度 Agent 将子任务**指派给 specialist Agent**，并约定输入、输出、超时与回传格式。

## 先理解什么（入门）

委派 = 分包。调度者不做具体活，但要验证子结果是否满足接口契约，否则拒收或要求重做。

## 再理解什么（进阶）

- **动态 vs 静态委派**：静态在流程图里写死；动态由模型根据任务类型选人。
- **并行委派**：无依赖子任务并行以缩短 wall time。
- **失败升级**：子 agent 多次失败升级到人或更强模型。

## 落地要点（实践）

- 委派消息包含：目标、约束、上下文指针、截止时间。
- 子 agent 只读共享状态区，写结果到指定槽位，避免互相覆盖。
- 对委派链深度设上限。

## 常见坑

- 子 agent 返回非结构化长文，调度者难解析。
- 无超时导致整个 crew 挂死。
