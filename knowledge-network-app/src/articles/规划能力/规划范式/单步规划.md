# 单步规划

## 一句话定义

在**一次模型调用**内给出完整计划或答案，中间不与环境交互，适合信息充分、风险低的任务。

## 先理解什么（入门）

Single-shot 成本低、延迟小，但无法利用外部反馈修正。典型场景：模板化生成、简单分类、短问答。

## 再理解什么（进阶）

- **与 RAG 组合**：先检索再单步生成，仍属「单步规划」若不再循环。
- **边界**：一旦需要验证假设或执行副作用操作，应切换到多步/ReAct。
- **提示约束**：要求输出 JSON 计划表，便于程序执行下一步。

## 落地要点（实践）

- 用评测集标定「可单步」任务类型，其余默认多步。
- 对单步输出加强 schema 校验，失败则降级到 replan。

## 常见坑

- 把需要实时数据的任务硬塞单步，产生幻觉。
