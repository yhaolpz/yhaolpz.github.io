# 多步规划

## 一句话定义

把目标拆成**有序子步骤**，可在一轮生成完整计划（静态），也可执行中动态追加（动态）。

## 先理解什么（入门）

多步规划回答「先做什么后做什么」。与 ReAct 不同：规划阶段可以暂不调用工具，只输出步骤表，再由执行器逐步落实。

## 再理解什么（进阶）

- **依赖图**：步骤间有 DAG 依赖时，应用拓扑排序执行。
- **重规划触发**：某步失败、超时或新信息出现时要插入重规划。
- **粒度控制**：步骤太细管理成本高，太粗难以定位失败。

## 落地要点（实践）

- 计划对象含：id、描述、依赖、重试策略、预计工具。
- 与状态机或工作流引擎集成，持久化到检查点。
- UI 展示「当前第 k 步」增强用户信任。

## 常见坑

- 计划与真实系统能力不匹配（假设了不存在的 API）。
- 无幂等设计导致重试重复写数据。
