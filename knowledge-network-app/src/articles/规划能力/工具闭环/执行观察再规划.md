# 执行观察再规划

## 一句话定义

经典循环：**执行动作 → 观察环境反馈 → 更新信念 → 再决定下一步**，是 ReAct 与许多控制论系统的核心骨架。

## 先理解什么（入门）

「观察」应是机器可读的结构化信号：HTTP 状态、JSON 字段、UI diff。纯自然语言观察易歧义。

## 再理解什么（进阶）

- **部分可观测**：状态不全时需信念状态（belief）而非真状态。
- **延迟观测**：异步任务要轮询或 webhook，规划层需等待节点。
- **与人类在环**：观察到人拒绝时直接进入 replan 或终止。

## 落地要点（实践）

- 统一 Observation schema 跨工具。
- 设置「无进展检测」：连续 k 步观测无新信息则停止。
- 将关键观察写入 tracing 便于复盘。

## 常见坑

- 观察里夹带过大 payload 再次撑爆上下文。
- 未区分「工具返回错误」与「业务规则拒绝」。
