# 向量数据库

## 一句话定义

为向量检索优化的数据库或索引服务，提供**持久化、过滤、副本、水平扩展**等能力，支撑大规模 Agent 记忆与 RAG。

## 先理解什么（入门）

内存里 `numpy` 暴力检索只适合 demo。生产需要：分片、持久化、混合过滤（metadata + vector）、备份与权限。

## 再理解什么（进阶）

- **HNSW / IVF**：常见近似索引算法，在召回与延迟间折中。
- **一致性**：写入后读、副本延迟对「刚写入就要查」场景的影响。
- **混合查询**：向量 + SQL 过滤（部门、时间、标签）。

## 落地要点（实践）

- 选云托管还是自建：看合规、运维成本、SLA。
- 为 collection 设计清晰命名与生命周期（测试/生产隔离）。
- 压测 p95 查询延迟与 QPS。

## 常见坑

- 未建 metadata 索引导致过滤扫全表。
- 版本升级不兼容索引格式，迁移停机过长。
