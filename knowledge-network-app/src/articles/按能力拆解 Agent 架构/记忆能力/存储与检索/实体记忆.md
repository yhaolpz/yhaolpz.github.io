# 实体记忆

## 一句话定义

围绕**具体对象**（人、项目、设备、订单）聚合相关事实与事件，支持「问到这个实体就能调出全貌」的记忆单元。

## 先理解什么（入门）

与「整段对话向量」不同，实体记忆强调结构化槽位：属性、关系、时间线。类似轻量 CRM 或知识卡片。

## 再理解什么（进阶）

- **实体解析（EL）**：同一字符串可能指不同实体，需要上下文消歧。
- **合并**：同一用户多账号、同一项目改名，需要实体对齐算法。
- **与图谱**：实体可为图节点，事实为边或属性。

## 落地要点（实践）

- 每个实体有 owner、可见范围、最后更新时间。
- 写入新事实时检查与旧事实是否矛盾并提示。
- 对高价值实体提供「变更历史」视图。

## 常见坑

- 实体 id 不稳定导致记忆串档。
- 未限制实体属性数量，对象膨胀。
