# 记忆写入策略

## 一句话定义

决定**何时、写入什么粒度、写到哪一层存储**的规则，避免记太多噪声或记太晚来不及用。

## 先理解什么（入门）

不是所有对话都值得进长期记忆。写入触发可以是：显式用户指令、关键实体出现、任务成功/失败边界、周期性摘要。

## 再理解什么（进阶）

- **去重与合并**：同一偏好多次提及应合并而非重复存。
- **置信度**：从模型推断的事实要标置信度，低置信不入库或需确认。
- **分层**：热数据在 Redis，温数据在向量库，冷归档在对象存储。

## 落地要点（实践）

- 用策略表：事件类型 → 写入目标 → 保留 TTL。
- 写入失败要可重试且不阻塞主对话。
- 定期离线任务清理矛盾记录。

## 常见坑

- 把临时验证码、一次性链接写入长期记忆。
- 写入与读取权限模型不一致。
