# 自适应规划

## 一句话定义

在执行过程中根据**观测与反馈**调整原计划，而不是死板执行初版计划（Adaptive / dynamic planning）。

## 先理解什么（入门）

真实环境常有异常：API 变更、数据缺失、用户改需求。自适应强调「监控偏差 → 触发重规划」。

## 再理解什么（进阶）

- **触发器设计**：错误码、置信度阈值、用户否定词等。
- **局部重规划 vs 全局重算**：小偏差只改子树，大偏差整体重来。
- **代价**：频繁调用大模型规划会增加成本，可用小模型做「是否需要重规划」分类器。

## 落地要点（实践）

- 在状态里保存 `plan_version` 与变更原因审计。
- 限制单日重规划次数防爆循环。
- 与用户沟通「因 X 原因此前步骤作废，将执行新方案」。

## 常见坑

- 重规划未清理已执行副作用，造成不一致。
- 触发器过松导致抖动，过严则卡死在错误路径。
