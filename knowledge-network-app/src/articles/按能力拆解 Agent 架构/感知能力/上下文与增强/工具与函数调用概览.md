# 工具与函数调用概览

## 一句话定义

让模型在需要时输出**符合 schema 的结构化调用请求**，由运行时映射到真实 API / 函数，是 Agent 连接外部世界的桥梁。

## 先理解什么（入门）

「工具」可以是 HTTP API、数据库查询、本地函数。模型侧看到的是**名称 + 描述 + 参数 JSON Schema**；执行侧负责鉴权、传参、解析返回值。

## 再理解什么（进阶）

- **严格模式**：JSON Schema `strict` 可减少参数幻觉（视模型与 API 支持而定）。
- **并行调用**：多个只读工具可并行；有副作用的应串行并加幂等键。
- **观测**：每次调用记录 latency、错误码、重试次数。

## 落地要点（实践）

- 工具描述用动词开头、写清前置条件与失败语义。
- 返回体尽量结构化，少用大段自然语言让模型二次解析。
- 对高风险工具做人审或二次确认。

## 常见坑

- Schema 过宽，模型乱填；过窄，无法表达业务。
- 未处理「模型声称调了工具但实际未调」的攻防场景。
