# 结构化与日志数据

## 一句话定义

把 API、数据库、日志等**已结构化或半结构化**的数据转成模型可用的上下文，而不是整段粘贴原始 dump。

## 先理解什么（入门）

企业里大量信息已经是 JSON、表格、SQL 结果、访问日志。对 Agent 来说，这类输入比散文更易解析，但也更容易**超长**或**含噪声字段**（时间戳、trace id、冗余列）。

## 再理解什么（进阶）

- **选字段**：只把与当前任务相关的列/键放进上下文，能显著省 token、减幻觉。
- **规范化**：统一时间格式、单位、枚举值，减少模型「猜格式」。
- **脱敏**：日志常含 IP、账号、token；进模型前要做脱敏或哈希。

## 落地要点（实践）

- 大结果集要分页或抽样，并说明「仅展示前 N 条」。
- 对日志可先做聚合（按错误码计数、按耗时排序 TopK）再交给模型解读。
- 与 RAG 结合时：结构化元数据（标签、版本）可作为过滤条件。

## 常见坑

- 把百万行日志原样塞进上下文导致爆窗或费用爆炸。
- 未说明数据来源与时间范围，模型容易过度推断因果。
