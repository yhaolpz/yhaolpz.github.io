# 案例与日志经验

## 一句话定义

把历史工单、故障复盘、成功案例与相关日志**提炼为可检索经验**，供以后类似问题快速对齐处理方式。

## 先理解什么（入门）

与 FAQ 不同，案例常含**时间线、根因、修复动作、验证步骤**。适合运维、客服、On-call Agent。

## 再理解什么（进阶）

- **结构化字段**：现象 / 影响面 / 根因标签 / 修复命令 / 回滚方案。
- **隐私**：日志中的账号、IP、token 需脱敏后再索引。
- **时效**：同样报错码在不同版本可能含义不同，要绑定软件版本。

## 落地要点（实践）

- 结案工单自动进「经验库」，并由人审抽检。
- 检索时优先近半年同产品线的案例。
- 与 metrics 联动：修复后错误率是否下降。

## 常见坑

- 把未验证的猜测写进「结论」被当作事实传播。
- 案例过长，切块破坏因果链。
