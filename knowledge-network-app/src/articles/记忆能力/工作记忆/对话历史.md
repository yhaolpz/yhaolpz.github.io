# 对话历史

## 一句话定义

按时间顺序保留的用户与助手消息序列，是**短期上下文**最直接的形式。

## 先理解什么（入门）

多轮对话依赖历史；但无限堆积会爆窗口。工程上要在「够连贯」与「够短」之间折中。

## 再理解什么（进阶）

- **角色标记**：user / assistant / tool 分段清晰，避免模型把工具输出当成用户说的。
- **截断策略**：保留首轮系统约束 + 最近 N 轮 + 可选摘要。
- **分支与会话 fork**：同一 session 可能有多个分支，需要 session_id + branch_id。

## 落地要点（实践）

- 持久化到 DB 时加密与脱敏。
- 对长会话提供「折叠已读」与「重新摘要」按钮。
- 评估：去掉中间若干轮后任务是否仍可完成。

## 常见坑

- 把中间系统提示截断掉，导致安全策略丢失。
- 未存 tool_call_id，重放对话时无法对齐工具结果。
