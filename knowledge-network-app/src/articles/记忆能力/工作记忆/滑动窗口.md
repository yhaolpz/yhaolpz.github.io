# 滑动窗口

## 一句话定义

只保留对话或事件中**最近固定长度（轮数或 token）**的一段，超出部分丢弃或摘要，是控制上下文大小的朴素策略。

## 先理解什么（入门）

实现简单：适合对「远历史」不敏感的任务。与「摘要 + 全保留关键」相比，窗口策略信息损失更硬，但延迟与成本可预期。

## 再理解什么（进阶）

- **按轮 vs 按 token**：按轮可能某轮超长仍爆窗；按 token 更稳但实现复杂。
- **锚点保留**：永远保留第一条用户目标与系统约束，中间滑动。
- **与向量记忆结合**：被滑出窗口的内容可先写入长期检索库。

## 落地要点（实践）

- 在 UI 提示用户「更早消息已折叠」。
- 对工具调用链，窗口边界不要切断未完成的 call/result 对。

## 常见坑

- 窗口切在半个 function call 中间导致 API 报错。
- 用户引用「三天前说过的话」已不在窗口内且无长期记忆。
